# Реализация управления инцидентами ИБ для DFIR-IRIS

## Обзор

Реализована поддержка **Положения о мониторинге событий и реагировании на инциденты информационной безопасности** ФГАОУ ВО "Тюменский государственный университет" в веб-интерфейсе DFIR-IRIS для управления кейсами (инцидентами).

## Что было реализовано

### 1. База данных и модели

**Новые таблицы:**
- `incident_category` - 8 категорий инцидентов (таблица 5.1 Положения)
- `system_type` - типы систем: целевая/ключевая/вспомогательная
- `incident_importance` - важность: высокая/средняя/низкая
- `incident_priority` - приоритет 1-9 (таблица 5.2)
- `incident_type` - типы инцидентов (преднамеренный/случайный/естественный/неизвестно)
- `undesirable_event` - недопустимые события
- `protagonist_motivation` - мотивация причастных лиц
- `playbook` - плейбуки реагирования

**Расширенные поля в таблице `cases`:**
- Категоризация: `incident_category_id`, `system_type_id`, `importance_id`, `priority_id`
- Тип инцидента: `incident_type_id`, `is_undesirable_event`, `undesirable_event_id`
- Хронология: `incident_occurrence_date`, `incident_discovery_date`, `incident_report_date`, `incident_duration_seconds`
- Информация о сообщающем: `reporter_name`, `reporter_phone`, `reporter_email`, `reporter_location`, `reporter_organization`
- Этапы реагирования: `response_phase`, `investigation_start_date`, `investigation_end_date`, `investigation_completion_date`
- Плейбук: `playbook_id`
- Дополнительная информация: `affected_assets_info`, `business_impact_description`, `vulnerability_info`, `perpetrator_description`, `corrective_measures_org`, `corrective_measures_tech`, `investigation_report_path`

### 2. API Endpoints

**Базовый URL:** `/manage/incident`

**Эндпоинты:**
- `GET /categories/list` - список категорий инцидентов
- `GET /system-types/list` - список типов систем
- `GET /importance-levels/list` - уровни важности
- `GET /priority-levels/list` - уровни приоритета (1-9)
- `GET /incident-types/list` - типы инцидентов (группировка по категориям)
- `GET /undesirable-events/list` - недопустимые события
- `GET /motivations/list` - мотивации причастных лиц
- `GET /playbooks/list` - список плейбуков
- `GET /playbook/<id>` - детали плейбука
- `POST /case/<id>/update` - обновить данные инцидента для кейса
- `GET /case/<id>` - получить данные инцидента для кейса
- `POST /calculate-priority` - **автоматический расчёт важности и приоритета** по таблицам 5.1 и 5.2

### 3. Автоматический расчёт приоритета

**Логика (согласно таблицам 5.1 и 5.2 Положения):**

**Таблица 5.1 - Определение важности:**
- Категории 1-3: Всегда **Высокая** важность
- Категория 4 (разведка): Средняя для вспомогательных, Высокая для ключевых/целевых
- Категории 5-6: Низкая для вспомогательных, Средняя для ключевых/целевых
- Категория 7 (ошибка пользователя): Средняя для ключевых/целевых, Низкая для вспомогательных
- Категория 8 (иной): Средняя для целевых, Низкая для остальных

**Таблица 5.2 - Определение приоритета:**
```
Тип системы / Важность | Низкая | Средняя | Высокая
-----------------------|--------|---------|--------
Вспомогательная        |   9    |    8    |   6
Ключевая               |   7    |    5    |   3
Целевая                |   4    |    2    |   1
```

### 4. Frontend компоненты

**Модальное окно:** `templates/modals/incident_management.html`
- Секция 1: Категоризация инцидента (категория, тип системы, важность, приоритет, тип, недопустимое событие)
- Секция 2: Информация о сообщающем лице
- Секция 3: Хронология инцидента
- Секция 4: Этапы реагирования (регистрация, сдерживание, ликвидация, восстановление, подведение итогов)
- Секция 5: Дополнительная информация (активы, влияние на бизнес, уязвимости, нарушитель, меры)

**JavaScript модуль:** `static/assets/js/iris/case.incident.js`
- Загрузка справочников при открытии модального окна
- Автоматический расчёт важности и приоритета при выборе категории и типа системы
- Загрузка существующих данных кейса
- Сохранение всех полей через API
- Обработка дат и времени

### 5. Миграция БД

**Файл:** `alembic/versions/a1b2c3d4e5f6_add_incident_management_fields.py`

Миграция создаёт все таблицы, добавляет поля в `cases`, устанавливает foreign keys и заполняет справочники данными согласно Положению.

## Как использовать

### 1. Применить миграцию

```bash
# Запустить Docker контейнеры
docker compose down
docker compose up -d

# Применить миграцию (внутри контейнера)
docker compose exec web alembic -c app/alembic.ini upgrade head
```

### 2. Добавить кнопку в интерфейс кейса

В шаблоне страницы кейса добавить кнопку:

```html
<button class="btn btn-primary" 
        data-bs-toggle="modal" 
        data-bs-target="#incidentManagementModal"
        data-case-id="{{ case.case_id }}">
  <i class="fas fa-shield-alt"></i> Управление инцидентом ИБ
</button>
```

### 3. Подключить модальное окно и скрипт

```html
<!-- В шаблоне кейса -->
{% include 'modals/incident_management.html' %}

<script src="{{ url_for('static', filename='assets/js/iris/case.incident.js') }}"></script>
```
