# MP10 28.0: действующий контракт сбора событий

Этот документ заменяет прежние предположения о вспомогательных методах SDK.
Эталон для установки пользователя — предоставленный им рабочий запрос Postman
и фактический JSON-ответ. Самостоятельно добавленные v2-маршруты событий удалены.

## Единственный запрос событий

`POST /api/events/v3/events/`

Параметры URL: `incidentId`, `offset`, `limit=250`, `noCount=true`.
На следующих страницах также передаётся полученный `token`.
Заголовок `Content-Type: application/json`; Bearer-токен берётся из конфигурации
и не включён в документацию или фикстуры.

Тело:

```json
{
  "filter": "select(поля из рабочего запроса) | sort(time desc)",
  "timeFrom": 1792486213,
  "timeTo": 1792486218
}
```

Числа времени приведены из примера; в автоматическом опросе границы вычисляются
динамически. Полный список 335 полей зафиксирован в тестовой фикстуре
`v3/backend/tests/fixtures/maxpatrol_v3_select.txt` и проверяется тестом запроса.
Все страницы используют одинаковые границы и один фильтр.

## Дерево без сетевых запросов

Ответ содержит `errors`, `events`, `totalCount`, `token`. Объекты событий уже
содержат нормализованные поля, исходный `body` при наличии и UUID связей `subevents`.
Модуль сохраняет эти поля, включая `null` и пустые контейнеры, без переинтерпретации.
Дерево и карта связей строятся только из всех страниц этого ответа.
UUID экземпляра берётся из `uuid` или `_meta.id`; `id` правила нормализации
не используется для идентификации экземпляра.

При повторяющихся UUID и циклах применяются ссылки на уже полученные объекты.
Если дочерний UUID отсутствует, сохраняются `missing_uuids` и `complete=false`.
Дополнительные endpoints событий и запросы по предположениям не выполняются.
При отсутствии данных нельзя утверждать, что дочернее событие удалено или отсутствует
в SIEM: подтверждено только то, что его нет в предоставленной выдаче.

На пользовательском ответе выполнен локальный прогон: 12 событий, один родитель
и 11 дочерних UUID; сохранены 11 исходных `body`. Исходные приватные события
не копировались в репозиторий. Доступ к SIEM при проверке не выполнялся.

## Контроль реализации

- Сетевой клиент больше не содержит вспомогательных v2-методов событий.
- Построитель дерева не принимает HTTP-клиент и не может отправить запрос.
- Регрессионный тест проверяет отсутствующий дочерний UUID: разрешён только
  исходный v3-запрос, состояние отмечается как неполное.
- В журнале запуска `request_revision=mp10-list-v2-events-v3-335-1`.

## Данные инцидентов: рабочий POST списка

Пользователь подтвердил `POST /api/v2/incidents/` с `offset=0`, `limit=50`,
`groups.filterType=no_filter`, `filterTimeType=creation`, `queryIds=[all_incidents]`.
`timeFrom` — ISO UTC из lookback, `timeTo=null`. Выборка полей:
`key,name,category,type,status,created,assigned`; предикат `status != "Closed"`;
сортировка: `created descending`, `status ascending`, `severity descending`.

Модуль использует данные возвращённых строк, а не отдельный GET карточки.
Таким образом, при обычном импорте выполняются только два типа POST:
список инцидентов и список событий. Тест сверяет тело списка с предоставленным
пользователем JSON и запрещает любые другие запросы в полном цикле импорта.
Отсутствующие подробности не считаются полученными; ранее сохранённые
дополнительные поля остаются при обновлении существующих материалов.
