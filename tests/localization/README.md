# Локализация интерфейса IRIS (English default + Russian)

Дополнительная локализация веб-интерфейса. Английский остаётся языком по
умолчанию и языком-источником; русский выбирается пользователем и сохраняется
между запросами и повторными входами.

## Что реализовано

* **Движок i18n** — `source/app/i18n.py`
  * каталоги в стандартном формате GNU gettext `.po`
    (`source/app/locales/{en,ru}/LC_MESSAGES/messages.po`), парсятся
    прямо из `.po` без внешних зависимостей;
  * `gettext`, `ngettext`, `pgettext`, `lazy_gettext` (для меток WTForms) и
    Jinja-глобали `_`, `gettext`, `ngettext`;
  * активная локаль в `ContextVar` — потокобезопасно, без «протечки» между
    параллельными воркерами ASGI;
  * проверка списка поддерживаемых локалей (`SUPPORTED_LOCALES`), при
    неизвестном значении — откат к `en`.
* **Jinja** — подключение расширения `jinja2.ext.i18n`, поддержка
  `{% trans %}`. Все правки в шаблонах — **явные** вызовы `{{ _('...') }}`,
  никакой автозамены DOM и никакой трансляции пользовательских данных.
* **JavaScript** — `source/app/static/assets/js/iris/i18n.js` и
  `window.IRIS_I18N` (каталог внедряется через
  `templates/includes/i18n_scripts.html`). Функции `t()`, `ngettext()`,
  подстановка `{placeholder}`, правила множественного числа для ru.
* **Переключатель языка** — `templates/includes/language_switch.html`:
  * на странице входа и MFA (`login.html`, `mfa_setup.html`, `mfa_verify.html`);
  * в верхней панели приложения (`includes/navigation.html`).
  * POST-форма с CSRF-токеном, проверка локали, безопасный относительный
    редирект (защита от open redirect). Маршрут —
    `source/app/blueprints/i18n/i18n_routes.py` (`POST /i18n/set-locale`).
* **Сохранение выбора** — подписанная сессия (`session['locale']`) плюс
  долгоживущая подписанная cookie `iris_locale` (SECRET_KEY, срок 1 год).
  Пользователь без входа и после входа получает один и тот же выбор.

### Почему per-user через сессию/cookie, а не колонка в БД

Предпочтительный для проекта минимум риска: добавление колонки `ui_language` в
таблицу `user` требует Alembic-миграции и меняет схему, а тесты приёмки
миграции/upgrade сравнивают схему с официальным релизом v2.4.29. Чтобы не
нарушать этот контракт, выбор хранится в подписанной сессии
(по сути per-user, так как сессия привязана к аутентифицированному
пользователю) и в подписанной cookie. Если потребуется именно колонка БД —
это отдельное решение с отдельной миграцией.

## Тесты

```bash
# минимум зависимостей (без БД/Celery/Socket.IO)
python -m pip install -r tests/localization/requirements.txt
python -m pytest tests/localization -q
```

Активное дерево UI включает 87 HTML-шаблонов в `source/app/blueprints/*/templates` (activities, alerts, case, custom_dashboard, dashboard, datastore, demo_landing, dim_tasks, manage, overview, profile, search и statistics), а также пользовательские сообщения Python и JavaScript. Инвентаризация ниже учитывает только явные вызовы переводчика и не маркирует пользовательские данные, enum/API-идентификаторы или логи.

Набор `tests/localization`:

* `test_i18n_core.py` — парсинг `.po`, валидация локалей, множественное число,
  откат к msgid, изоляция локали между потоками, `lazy_gettext`.
* `test_i18n_catalog.py` — целостность ru-каталога (все записи переведены,
  плейсхолдеры сохранены), JSON-каталог для JS, парность py/js.
* `test_i18n_templates.py` — Jinja-глобали, партиал переключателя, внедрение
  JS-каталога, `lang` и перевод страницы ошибки, а также **компиляция всех
  шаблонов** (ловит синтаксические ошибки после правок).
* `test_i18n_switch.py` — маршрут `/i18n/set-locale`: CSRF, проверка локали,
  безопасный редирект, сохранение выбора, переговоры по `Accept-Language`,
  POST-only.
* `test_i18n_coverage.py` — покрытие по извлечённому инвентарю строк.

Изоляция модулей для тестов — `tests/localization/conftest.py` (регистрирует
псевдопакет `app`, как это делает `tests/migration/test_auth_forms.py`, чтобы не
загружать `app/__init__.py` с инициализацией БД).

### Инструмент покрытия

```bash
python tests/localization/extract_strings.py --source source/app
```

Извлекает **только явные** вызовы `_()/gettext()/lazy_gettext()/ngettext()/
pgettext()` из шаблонов и Python и сравнивает с каталогами. Пользовательские
данные не транслируются, поэтому это нижняя оценка покрытия, и её нельзя
«накрутить». Текущий результат: **1764 из 1764** извлечённых строк переведены в русском каталоге. Инвентарь включает явные вызовы `IRIS_I18N.t()` в собственных JavaScript-файлах приложения и метки форм `lazy_gettext(u'...')`. Этот показатель учитывает обёрнутые строки, а не весь текст приложения.

## Покрытие интерфейса и границы

* Переведены оболочка, вход и MFA, страницы ошибок, панель управления,
  страницы инцидента (сводка, заметки, активы, IOC, задачи, временная шкала,
  граф и доказательства), оповещения, хранилище, поиск, обзор, статистика,
  профиль, администрирование и пользовательские панели.
* Подключены переводы статических подписей и подсказок в 97 шаблонах,
  сообщений, действий и генерируемой разметки JavaScript, меток и обязательных
  полей WTForms. В отдельных макетах инцидента и центрированных страниц
  словарь подключается до собственных скриптов; навигация инцидента содержит
  переключатель языка.
* При выборе русского локализованы стандартные подписи DataTables и
  bootstrap-select. Подстановки `_START_`, `_END_`, `_TOTAL_`, `_MENU_`
  и `{0}`/`{1}` сохраняются для обработки библиотеками.
* Пользовательские названия, содержимое заметок, значения API и технические
  идентификаторы не переводятся. Ответы API, журналы, сообщения сторонних
  модулей и редактируемые справочники могут содержать английский текст.
  Покрытие явных вызовов не является гарантией отсутствия английского текста
  в этих данных или во всех динамических ветках интерфейса.
* `test_i18n_client.py` проверяет словарь JavaScript, подстановки, множественное
  число, подписи таблиц и обратное скрытие пароля. Для этих проверок нужен Node.js;
  без него они пропускаются. Тесты шаблонов также проверяют диалог заказчика,
  экранирование пользовательских данных и метки/ошибки форм в обоих языках.
* Проверки от 09.10.2026: **45 тестов проходят**, все 42 собственных JavaScript-файла
  проходят `node --check`. Проверка Docker ниже относится к отдельной приёмке;
  пересборка работающего стека в рамках дополнения переводов не выполнялась.

## Docker-приёмка (изолированно)

Только отдельный проект `iris-upgrade-2-4-29-fastapi`:

```bash
docker compose -p iris-upgrade-2-4-29-fastapi -f docker-compose.upgrade-validation.yml config
docker compose -p iris-upgrade-2-4-29-fastapi -f docker-compose.upgrade-validation.yml up -d --build
# UI: https://localhost:18543  (app напрямую: http://127.0.0.1:18082)
```

Порты 18082/18543, тома с префиксом `iris-upgrade-2-4-29-fastapi_*` — основной
стек (`iriswebapp_*`) и его данные не затрагиваются.
