# Анализ оповещения в Yuki одной кнопкой

Согласовано 26 октября 2026: отдельная кнопка «Анализировать в Yuki» в карточке
оповещения открывает новый диалог и немедленно отправляет готовый промпт.
Используется существующий механизм `currentAlert` и MCP-инструменты оповещений;
изменения БД и новый backend endpoint не нужны.

Промпт просит изучить исходные события, активы и IOC, оценить TP/FP с
доказательствами, предложить действия и явно обозначить нехватку данных.
Автоматически изменять оповещение промпт запрещает. Исходное содержимое
не вставляется в текст кнопкой: Yuki получает ID и читает данные через
существующие инструменты с проверкой прав пользователя.

Кнопка видна, когда Yuki включён. Новый запуск блокируется во время создания
диалога, генерации ответа и ожидания согласования действий. Старый диалог
остаётся в истории. При запуске из модального просмотра он закрывается,
чтобы не перекрывать Yuki. Панель разворачивается при переходе к новому диалогу.
Ошибки создания и Socket.IO показываются в панели; ошибочный запрос не должен
отправляться в предыдущий диалог.

План проверки: тестировать отдельный диалог с правильным ID, немедленную
отправку, повторные клики, занятой чат, ошибки создания и подключения.
Проверить компиляцию изменённых Svelte-компонентов и локализацию EN/RU.
На удалённом сервере требуется обновление frontend и проверка Yuki с
настроенными провайдером, MCP и рабочим Socket.IO.
