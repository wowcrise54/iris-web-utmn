# IRIS v3.0.0-beta.6 — FastAPI и EN/RU

Рабочий адрес: https://localhost:18543. Backend: http://127.0.0.1:18082.
Проект: `iris-upgrade-2-4-29-fastapi`.

## Запуск и пересборка

Выполнять из `D:/Diplom/iris-web-utmn`; актуальные правила — в корневом `AGENTS.md`.

```powershell
docker compose -p iris-upgrade-2-4-29-fastapi -f docker-compose.upgrade-validation.yml -f docker-compose.saved-data.yml -f docker-compose.v3.yml -f docker-compose.v3-live.yml ps
docker compose -p iris-upgrade-2-4-29-fastapi -f docker-compose.upgrade-validation.yml -f docker-compose.saved-data.yml -f docker-compose.v3.yml -f docker-compose.v3-live.yml build app frontend nginx
docker compose -p iris-upgrade-2-4-29-fastapi -f docker-compose.upgrade-validation.yml -f docker-compose.saved-data.yml -f docker-compose.v3.yml -f docker-compose.v3-live.yml up -d --no-build --pull never
```

Основной остановленный стек `iriswebapp_*` не относится к этому запуску.
Dockerfile backend повторно использует сохранённый образ 2.4.29 как базу
зависимостей; новый код копируется после удаления старого кода из слоя образа.
Резервный тег старого приложения: `iris-v2-rollback:20261010-160726`.
`Dockerfile.runtime` использовался для последнего переноса готовой локальной
сборки UI в Linux-образ с уже установленными зависимостями; обычная пересборка
через Compose собирает актуальные Svelte-исходники стандартным Dockerfile.

## Что перенесено

- Исходники beta.6 зафиксированы по коммитам в корневом `UPSTREAM_VERSION.md`.
- FastAPI/Uvicorn владеют маршрутизацией; Flask/WSGI-приложение не используется.
  Бизнес-обработчики v3 сохранены, инфраструктурные импорты перенесены в native
  адаптеры; standalone SQLAlchemy/Marshmallow и контексты запроса сохранены.
- Native ASGI Socket.IO: namespace-контексты, комнаты, совместное редактирование
  Yjs и обмен с worker через JSON-очередь RabbitMQ. Закреплён python-socketio 5.17.0.
- PostgreSQL 18: обе базы `iris_db` и `iris_tasks` восстановлены логически в новый
  external-том. Старые тома PG12/файлов не удалялись.
- Локальная revision `e5d79b8c4a55` сохранена в цепочке Alembic. Отдельная
  `utmn_v3_permissions01` переносит значения разрешений v2 по смыслу перед
  стандартными миграциями v3; полный прежний администратор получает полный
  набор v3, ограниченные группы не получают новые права war rooms/кластеров.
  Статистика переместилась в дашборды, её прежнее read-разрешение отображается
  на чтение дашбордов. Итоговая upstream revision: `d2a6b8c1e374`.

## Локализация

Переключатель English/Русский доступен на всех страницах, включая вход.
Английский — язык по умолчанию; выбор хранится в HttpOnly cookie `iris_ui_locale`
на год. Смена языка проверяет origin и допустимые значения, затем перезагружает
страницу. SSR использует локаль конкретного запроса и отдельный Svelte store
контекста; общей изменяемой серверной локали нет.

Словарь `frontend/src/lib/i18n/ru.json` переиспользует прежние переводы; новые
публичные строки дополнены автоматическим переводом с проверкой базовой
терминологии. Инвентарь содержит 3093 явно обёрнутые строки. Скрипты обработки
исходников не заменяют DOM и не переводят записи пользователя.
Это начальная локализация: формулировки новых подробных подсказок требуют
дальнейшей редакторской проверки; не все динамические/серверные сообщения и
редактируемые справочники переведены. Названия пользователей, статусы и данные
из БД сохраняются как введены. Прежняя подписанная cookie `iris_locale` не
преобразуется автоматически; при первом входе можно выбрать русский ещё раз.

## Подтверждённые проверки

- 53 регрессионных теста native адаптеров, форм, SQLAlchemy, ASGI Socket.IO и
  совместимости v3 прошли; 4 предупреждения зависимостей, без пропусков.
- 3 теста переводчика прошли; `svelte-check`: 0 ошибок, 9 предупреждений upstream.
- Production frontend собран. Проверены EN/RU, сохранение выбора, вход и кейс №2,
  страницы оповещений, war rooms и сценариев расследования; ошибок JS нет.
- Два клиента: Yjs-правка дошла до второго клиента и сохранилась в заметке;
  событие из worker доставилось через RabbitMQ. Временная заметка удалена на
  проверочной копии; в рабочую БД тестовые записи не переносились.
- Полная исправленная цепочка миграций повторена с исходного снимка во второй
  проверочной БД без ручного изменения прав.
- До открытия рабочего адреса проверены API, все прежние строки кейсов/алёртов,
  заметок, активов, IOC, задач/назначений, событий, полученных файлов/хранилища,
  хеши пароля пользователя и хеши сохранённых файлов в томах.

Фактические результаты: `native-tests-final.log`, `frontend/check-final.log`,
`frontend/browser-probe-live.log`, `frontend/realtime-probe.log`,
`data-comparison.json`, `cutover-result.json`. Логи и приватные runtime-снимки
игнорируются Git; `runtime/data-baseline.json` содержит исходные записи и не
предназначен для публикации.

Полный upstream E2E-набор, OIDC, MFA и внешние интеграции в этом переходе не
проверялись. Интеграции с legacy API следует адаптировать к внешнему `/api/v2`.

## Резервные копии и восстановление

`D:/Diplom/backups/iris-v3-cutover-20261010-160726`:
`iris_db.dump`, `iris_tasks.dump`, `file-volumes.tar.gz`, `workspace.tar.gz`,

Снимки сняты после остановки записи; дампы проверены `pg_restore --list`,
скопированы вне контейнеров и имеют SHA-256. Архив кода содержит приватную
конфигурацию и не предназначен для публикации.

Старые тома: `iris-web-utmn_upgrade-db`, `iris-web-utmn_upgrade-downloads`,
`iris-web-utmn_upgrade-templates`, `iris-web-utmn_upgrade-server-data`.
До возобновления записи v3 можно вернуть v2 с двумя прежними Compose-файлами
и сохранёнными образами. После открытия записи простой возврат потеряет новые
изменения: сначала закрыть доступ/запись, сохранить PG18 и новые файлы, затем
выбрать способ восстановления. Не выполнять `down -v` и не удалять тома.

`cutover.py` — выполненная однократная процедура с проверкой исходного стека;
повторно на работающей v3 она откажется выполняться. `port_backend.py` также
описывает первоначальное преобразование: его повторный запуск перезапишет
доработанные адаптеры, поэтому не используется для пересборки.
