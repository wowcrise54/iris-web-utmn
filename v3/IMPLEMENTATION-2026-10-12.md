# Выполнение плана review, локализации и API-паритета

Дата: 2026-10-12. Изменены активные `v3/backend` и `v3/frontend`, а также
передача трёх frontend Sentry-переменных в `docker-compose.v3.yml`.
Корневой `source/`, рабочие контейнеры, база, файловые тома и резервные копии
не изменялись. Изменения находятся в рабочей копии и не развёрнуты в текущем стеке.

## Что выполнено

- Sentry envelope tunnel закрывается с 503 при отсутствии/невалидности доверенного
  серверного DSN. Разрешён только HTTPS с совпадающими адресом, портом, путём,
  проектом и ключом. Внешний запрос строится из серверной конфигурации.
- Literal IP и все DNS-ответы проверяются на публичность; проверенный адрес
  используется непосредственно соединением. Внутренний ingest требует явного
  `IRIS_UI_ENVELOPE_ALLOW_PRIVATE=1`, которое не отменяет HTTPS и совпадение DSN.
- Входящий envelope ограничен 1 MiB, ответ ingest — 64 KiB; чтение тела и весь
  запрос ingest имеют отдельные пределы 10 секунд. Бинарные payload сохраняются.
- `/locale` и общий CSRF hook используют одну проверку нормализованного origin:
  собственный адрес либо явно перечисленный в `IRIS_ALLOW_ORIGIN`.
- Исправлены `Import case`, `Resolve` в шаге сопоставления импорта, `Escalate`,
  `Review`, а также действие `Archive` и подтверждённая терминология инцидентов.
- Статические фрагменты всех page titles, прямых и шаблонных confirmation
  messages и accessibility labels проходят через каталог. Проверены также
  defaults общих компонентов и подписи событий/каналов уведомлений.
- Удаление оповещений описано точно: удаляются сами оповещения, их зависимые
  записи и связи; связанные инциденты, активы и IOC сохраняются. Есть формы
  для одного и нескольких выбранных объектов.
- Переводчик поддерживает именованные подстановки после перевода шаблона.
  Названия, ID и другие подставляемые значения не переводятся повторно.
- Добавлен AST source guard на основе установленного Svelte compiler. Он
  обнаруживает непереведённый фрагмент и рядом с `irisT()`, и внутри шаблонной строки.
- Восемь функций legacy API получили v2 эквиваленты; старые маршруты сохранены
  без нового объявления deprecated. Контракты и права описаны в
  [backend/API_PARITY.md](backend/API_PARITY.md), OpenAPI пересоздан в UTF-8.
- Гистограмма `GET /dashboard/case_charts` явно отложена: у активного frontend
  нет потребителя. Legacy endpoint остаётся доступен.
- Backend README описывает FastAPI/ASGI и совместимые синхронные обработчики.

## Проверки

- Frontend: `npm run test:unit -- --run --maxWorkers=2` — 1 533 теста,
  115 файлов, все прошли. Ограничение параллелизма устранило таймауты старых
  upload-тестов на этой Windows-среде.
- `npm run check` — 0 ошибок, 9 существовавших предупреждений в 6 файлах.
- `npm run build` — production client/server и adapter-node собраны.
  Существующие предупреждения Svelte, устаревших browser databases,
  circular dependencies и размеров chunks не устранены этим планом.
- Backend: 155 тестов и 27 subtests прошли в отдельном контейнере существующего
  образа, с актуальным кодом, без сети и подключённых рабочих томов. Покрыты
  новые API-контракты, схемы, mass assignment, enum-модели, datastore и статистика.
- Контрактные проверки используют настоящую регистрацию маршрутов и permission
  checks; результаты БД и состояние аутентификации заданы тестовыми fixtures.
  Проверены 401/403, reduced user fields, некорректные фильтры, query scope,
  порядок пользователей, metadata кейса и сохранение `C++` после декодирования `q`.
- Backend ruff для всех изменённых Python-файлов и `git diff --check` прошли.
- Отдельный временный процесс окончательного production frontend проверен на
  `127.0.0.1:18549`: EN title `Log In`, RU title `Войти`, `html lang=ru`,
  `/locale` с allowed alternate origin — 200, чужой origin — 403,
  envelope без доверенного DSN — 503. Процесс остановлен после проверки.

## Пределы проверки и настройки

- Полный upstream backend unit-набор блокируется при collection пятью старыми
  тестовыми модулями, импортирующими отсутствующий Flask. Затронутые компоненты
  проверены отдельным набором выше; весь upstream набор не объявляется прошедшим.
- REST integration suite в `backend/tests/` создаёт и удаляет записи. Новые
  integration cases добавлены, но этот suite не запускался против рабочей БД.
- Рабочий стек не пересобирался. Проверены его labels и mounts: проект
  `iris-upgrade-2-4-29-fastapi`, адрес `https://localhost:18543`, PG18-том
  `iris-web-utmn-v3-20261010-160726-db`. Новый код ещё не используется этим стеком.
- Свободные сообщения backend/API и network diagnostics проверены в
  `ApiService` и case import flow и оставлены исходным текстом. Полный протокол
  локализованных серверных ошибок, внешний Sentry и authenticated browser E2E
  не входят в подтверждённые результаты этих проверок.
- Для tunnel серверный frontend `IRIS_UI_SENTRY_DSN` должен совпадать с browser
  DSN из backend runtime-config. Пустая/несовпадающая настройка отклоняет отправку.
  Подробности и лимиты приведены в [README.md](README.md).
- В customer statistics средняя длительность вычисляется по закрытым кейсам,
  включая случай, когда закрыты все кейсы; отличие от ошибочного legacy sum
  явно описано в контракте. `protagonists` загружаются только для case detail,
  без дополнительного запроса на каждый элемент списка.
- Предыдущий месяц в v2 означает полный календарный месяц, включая переход
  января к декабрю. Границы января и 31-дневного месяца покрыты отдельными тестами.
  Legacy endpoint сохраняет прежнее поведение для совместимости.
- После первого review исправлены ещё четыре случая: передача Sentry-настроек
  через Compose, plural-copy по всем выбранным ID независимо от кэша, camelCase
  `ariaLabel` props и календарные границы customer statistics. Для первых трёх
  проверены merged Compose и дополнительные frontend regression/source guards.
