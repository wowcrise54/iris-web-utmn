# MaxPatrol EDR в IRIS

Вкладка «Реагирование» в кейсе использует связанные алёрты, импортированные
активным модулем MaxPatrol SIEM. Связь проверяется по записи импорта, источнику
и клиенту. Для сопоставления события нужен ID события и
`event_src.asset`, совпадающий с одним из `asset_ids`.

При проверке действия IRIS получает `xdrAgentsIds` через `assets_grid`,
проверяет подключение и авторизацию единственного агента через `discovery`
и запрашивает его каталог `actions` для модулей удаления файлов, изоляции
узла, завершения процессов, блокировки IP и доменов. IRIS показывает команды,
которые агент вернул для события и для которых есть все указанные в каталоге
параметры. Допускаются строки, целые числа и логические значения. Пустой
список полей допускает действие без параметров. Для удаления нужен абсолютный
файловый путь, поэтому пути реестра Windows исключаются.

Оператор выбирает одну команду и видит узел и параметры до подтверждения.
IRIS отправляет её в `/modules/{module}/actions/{action}` с телом
`{"data": {...}}`. HAR подтверждает эту форму для `fr_remove_object_file`.
Вызовы других действий используют ту же форму и требуют проверки на тестовом
агенте установленной версии EDR.

Для запросов используется текущий URL и Bearer-токен модуля MaxPatrol SIEM.
Перед включением выполнения проверьте на вкладке, что сервисный токен
получает каталог EDR и показывает нужный тестовый агент. HAR не подтверждает
совместимость токена с EDR. При HTTP 401/403 проверьте способ авторизации
и разрешения сервисной учётной записи на стороне MaxPatrol.

Для разрешения исполнения задайте `IRIS_EDR_RESPONSE_ENABLED=true` в
окружении backend IRIS. Пользователю нужны полные права на кейс. После
подтверждения IRIS повторно сопоставляет цель и записывает попытку и статус
в историю кейса. Истёкшее или использованное подтверждение нужно получить
заново. Если исход запроса неизвестен, проверьте журнал MaxPatrol EDR
перед новым запуском.
