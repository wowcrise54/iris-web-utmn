# PT Sandbox 5.37 в IRIS

Цель интеграции: отправить файл инцидента на поведенческий анализ, дождаться результата,
сохранить полный ответ и исходные логи, отправить отдельное краткое сообщение в war room
и по отдельному запросу разобрать материалы встроенным Yuki.

## Подключение модуля

1. Открыть **Настройки → Модули → PT Sandbox → Просмотр / настройка**.
   Пакет `iris_ptsandbox_module` входит в backend и регистрируется выключенным.
2. Сохранить HTTPS-адрес и API-токен. Суффикс `/api/v1` необязателен.
   Для внутреннего центра сертификации можно указать PEM-файл, доступный по одинаковому
   пути в app и worker. Переключатель **Проверять TLS-сертификат (true / false)**
   по умолчанию включён (`true`). При `false` сертификат сервера не проверяется,
   включая использование указанного CA-файла; соединение по-прежнему использует HTTPS.
3. Нажать **Проверить подключение**. Проверка использует сохранённые настройки,
   проверяет health/version и получает список образов виртуальных машин. Файлы не отправляет.
4. Выбрать ID образа по списку, сохранить его, длительность анализа (10–600 секунд)
   и максимальный размер отправляемого файла (1–512 МиБ). После изменения параметров
   повторить проверку подключения.
5. Включить модуль. Перед отправкой модуль должен быть включён, настроен и иметь
   успешную проверку подключения к версии `5.37` или сборке `5.37.*`.

Токен шифруется существующим механизмом Fernet с ключом приложения. API и экспорт
конфигурации возвращают пустое значение и признак наличия токена; пустое сохранение
сохраняет ранее заданный токен. Смена `SECRET_KEY` требует повторного ввода токена.
Токен не следует отправлять в чат.

## Проверка файла

**Из инцидента:** вкладка **PT Sandbox**, выбор файла из хранилища инцидента,
проверка фактического имени/размера отправляемого объекта, выбор связанной war room,
подтверждение передачи файла и кнопка **Отправить на проверку**.
Без выбранной war room результат сохраняется в инциденте.

Для IOC и файлов с паролем IRIS хранит ZIP: отправляется именно сохранённый ZIP,
а пароль передаётся только PT Sandbox в параметрах распаковки. SHA-256 проверки
соответствует фактически отправленным байтам и может отличаться от хеша файла внутри ZIP.

**Из чата war room:**

```text
/sandbox check <ID инцидента> <ID файла> --confirm
```

ID файлов видны на вкладке PT Sandbox. Инцидент должен быть связан с этой war room.
Флаг `--confirm` означает согласие на передачу файла настроенной песочнице.
Нужны права записи в war room и полный доступ к инциденту. Команда есть в подсказках и `/help`.

## Результаты и восстановление

Проверка проходит состояния `queued → uploading → submitting → running → collecting`.
Celery получает результат отдельными запросами через 30 секунд; промежуточный вердикт
не публикуется как окончательный. Идентификатор задания хранится в PostgreSQL.
Периодическая задача worker восстанавливает зависшие локальные задания после перезапуска.

В war room приходит отдельное системное сообщение: файл, SHA-256, вердикт, полнота анализа,
до восьми обнаружений, количество сохранённых логов и ссылка на карточку проверки.
Полный JSON можно просмотреть и скачать. Данные остаются доступными при отключении модуля.

Если ответ на создание задания потерян, состояние становится `submission_unknown`.
Повторное создание автоматически не выполняется. Нужно проверить очередь PT Sandbox,
после чего явно подтвердить разбор ситуации в карточке IRIS. Это разблокирует новую
проверку файла, но не отменяет возможное задание на стороне песочницы.

Ошибка ожидания или частичная загрузка допускает возобновление получения **существующего**
задания. Это не отправляет файл повторно. Один период ожидания ограничен шестью часами.
Изменение адреса модуля блокирует продолжение задания на другой песочнице.

## Логи и Yuki

IRIS рекурсивно собирает ссылки из `logs` полного отчёта, включая вложенные объекты
и этапы анализа. Загружает их через публичный `storage/downloadArtifact` и проверяет SHA-256.
Исходные сжатые/бинарные файлы сохраняются без изменения в БД и доступны для скачивания
после проверки доступа к инциденту. Исполняемые файлы из массива artifacts автоматически
не загружаются.

Лимиты автоматической загрузки: 64 МиБ на лог, 256 МиБ на проверку, 128 логов.
Для недоступного, превышающего лимит или неверного лога сохраняется отдельная ошибка.
Такая проверка отображается как частичная; полный ответ Sandbox со всеми ссылками остаётся
в карточке. Это логи конкретного анализа, а не системные журналы всего сервера PT Sandbox.

Текстовые логи, включая gzip и zstd, читаются страницами по 12 000 символов.
Декодированный просмотр ограничен первыми 16 МиБ с явной отметкой об усечении.
Бинарные PCAP, видео и архивы можно скачать; Yuki не интерпретирует их как текст.

Кнопка **Проанализировать с Yuki** требует отдельного согласия на передачу отчёта и
текстовых логов настроенному AI-провайдеру. Она создаёт отдельный разговор в области
этого инцидента. Ответ Yuki сохраняется обычным механизмом истории чата и не заменяет
вердикт песочницы. Инструменты только читают данные:

- `iris_case_sandbox_list` — история проверок с пагинацией;
- `iris_case_sandbox_report_get` — сводка, метаданные логов и страница полного отчёта;
- `iris_case_sandbox_log_get` — страница текстового лога, ID, смещение и ссылка на источник.

Каждый вызов проходит существующий контроль доступа MCP. Отчёты и логи обозначены
как недоверенные данные; инструкции внутри них не должны выполняться. Доступность
инструментов также зависит от настроенных allowlist/denylist MCP и политики Yuki.

История проверок, отчёты и бинарные логи удаляются каскадно при удалении инцидента.
Удаление исходного файла сохраняет историю проверки. Резервная копия PostgreSQL включает
новые отчёты и логи, поэтому её размер будет расти с использованием модуля.

## Исследование API и библиотеки

В публичных источниках для названия из задачи `ptsandboxpy` найден проект
[`py-ptsandbox`](https://github.com/Security-Experts-Community/py-ptsandbox),
дистрибутив [`ptsandbox`](https://pypi.org/project/ptsandbox/).
Изучены его транспорт, публичные методы, модели отчётов/логов и требования зависимостей.
Совпадение с другим, непубличным проектом с именем `ptsandboxpy` не установлено.

Библиотека асинхронная, использует aiohttp/pydantic и содержит дополнительные UI/debug API.
В этом модуле применён небольшой синхронный транспорт `requests`, уже используемый IRIS:
worker работает синхронно, а исходный JSON необходимо сохранять без преобразования типизированными
моделями. UI/debug API, логин администратора Sandbox и обновление зависимостей IRIS ради SDK
не требуются. Добавлена зависимость zstandard для чтения исходных журналов.

Реализованные операции публичного API:

| Операция | Метод и путь относительно `/api/v1` |
|---|---|
| Состояние API | `GET maintenance/checkHealth` |
| Версия продукта | `GET maintenance/getVersion` |
| Образы ВМ | `POST engines/sandbox/getImages` |
| Загрузка файла | `POST storage/uploadScanFile` — исходные байты |
| Создание задания | `POST analysis/createScanTask`, `async_result=true` |
| Ожидание | `POST analysis/checkTask`, `allow_preflight=false` |
| Полный отчёт | `POST analysis/report` |
| Исходный лог | `POST storage/downloadArtifact`, `file_uri=sha256:…` |

Во время работы портал отвечал HTTP 403, поэтому полный текст этих разделов не был доступен.
Контракт сверялся с исходниками клиента и доступной официальной документацией публичного API.
**Совместимость с реальным PT Sandbox 5.37 не проверена:** адрес и токен реального стенда
не предоставлены. Проверка подключения подтверждает health/version/images, а не весь цикл
анализа или право скачать все виды логов. Полный реальный цикл проверяется после настройки
модуля на разрешённом тестовом файле.

## Проверки реализации

- Изолированные unit-тесты транспорта, обработки секретов/логов и критических переходов worker.
- `check_ptsandbox_runtime.py`: интерфейс модуля, шифрование, классификация и область инструментов,
  отказ анонимным запросам. Для ASGI TestClient нужен тестовый пакет httpx.
- `check_ptsandbox_schema.py`: миграция, частичный уникальный индекс, BYTEA, каскады и downgrade
  в отдельной схеме PostgreSQL с откатом.
- `check_ptsandbox_workflow.py`: реальная ORM и worker, имитатор песочницы, сохранение исходного
  gzip-лога, отдельное сообщение в чат и текстовая страница для Yuki. Все тестовые таблицы
  и данные находятся в отдельной схеме и откатываются.
- Проверка типов Svelte, production build и проверка сохранности данных рабочего стека
  при развёртывании.
