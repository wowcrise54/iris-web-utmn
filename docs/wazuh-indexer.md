# Wazuh Indexer → IRIS

Модуль `iris_wazuh_module` опрашивает Wazuh Indexer 4.x и создаёт один алёрт
IRIS для каждого подходящего документа. Он использует учётную запись **Indexer**,
а не Wazuh Server API. [API Indexer](https://documentation.wazuh.com/current/user-manual/indexer-api/reference.html)
поддерживает HTTP Basic и JWT; модуль использует Basic.

## Учётная запись Indexer

1. В Wazuh Dashboard откройте **Indexer management → Security → Internal users**
   и создайте отдельного пользователя для IRIS.
2. В разделе **Roles** создайте роль с шаблоном индексов `wazuh-alerts-4.x-*`
   и правом чтения `read`. На вкладке **Mapped users → Manage mapping**
   привяжите к ней созданного пользователя. Последовательность описана в
   [документации Wazuh по RBAC](https://documentation.wazuh.com/current/user-manual/user-administration/rbac.html).
3. Убедитесь, что роль разрешает поиск `indices:data/read/search`, чтение
   страниц `indices:data/read/scroll` и освобождение контекста
   `indices:data/read/scroll/clear`. Состав групп разрешений зависит от версии
   security-плагина; недостающие права добавьте после проверки на целевом
   Indexer. Подробнее — в [описании Scroll API](https://docs.opensearch.org/latest/api-reference/search-apis/scroll/).
   Права записи и администрирования модулю не нужны.

Indexer должен быть доступен по HTTPS из контейнера worker. Установите
сертификат выдавшего центра в доверенное хранилище worker и оставьте проверку
TLS включённой.

## Настройка и проверка IRIS

1. Откройте **Настройки → Модули** и найдите **Wazuh Indexer**. Если модуль
   отсутствует, добавьте установленный пакет `iris_wazuh_module` через
   **Добавить модуль**.
2. Укажите HTTPS-адрес Indexer, имя пользователя и пароль, шаблон индексов,
   ID клиента IRIS, ID критичности и статуса, интервал, таймаут, проверку TLS
   и минимальный уровень правила. Начальное значение уровня — `12`. Пароль
   шифруется штатным механизмом секретов IRIS; API v2 не возвращает его в
   настройках или при экспорте модуля.
3. Включите модуль. Граница первого сбора фиксируется при включении: события
   с более ранним временем не импортируются. Опрос выполняет существующий
   Celery worker.
4. Создайте новое тестовое срабатывание уровня не ниже порога. Проверьте в
   IRIS источник, время, правило и исходное содержимое. Убедитесь, что новое
   срабатывание ниже порога не создало алёрт.
5. При ошибке проверьте журнал worker по сообщениям `Wazuh collection` и
   `Wazuh poll failed`. HTTP 401/403 указывает на учётные данные или права;
   сообщения о TLS и соединении — на сертификат или доступность Indexer.

Для закреплённого локального стека журнал можно открыть из корня репозитория:

```powershell
docker compose -p iris-upgrade-2-4-29-fastapi -f docker-compose.upgrade-validation.yml -f docker-compose.saved-data.yml -f docker-compose.v3.yml -f docker-compose.v3-live.yml logs --tail 100 worker
```

Перед операциями с Docker соблюдайте `AGENTS.md` репозитория и убедитесь, что
указанный стек соответствует нужной установке.

## Позиция сбора и ограничения

Опрос читает scroll-снимок страницами по 200 документов, сортируя по времени
события и используя `_doc` как дополнительный ключ внутри снимка. Временное
перекрытие в пять минут позволяет подобрать события, ставшие доступными с
небольшим опозданием. Квитанции по источнику, имени индекса и ID документа
сохраняются в базе и предотвращают дубли, в том числе после перезапуска.
Блокировка PostgreSQL не допускает одновременный опрос одного источника.
При неполном ответе или ошибке позиция последнего завершённого окна сохраняется
для повтора. Уже созданные алёрты при повторном обнаружении не перезаписываются.

Перекрытие ограничено: документ может быть пропущен, если он стал доступен
для поиска более чем через пять минут после времени события. События с меткой
времени до первого включения не импортируются даже при поздней индексации.
Изменение адреса Indexer, шаблона индексов или клиента IRIS создаёт новую
позицию источника. Изменения уже импортированного документа обратно не
синхронизируются. При истечении scroll-контекста окно будет повторено.
Версию Wazuh, схему индексов, формат времени, доверие к CA и права роли нужно
проверить на целевой установке.

Скрипты интеграционной проверки PostgreSQL `v3/backend/tests/wazuh_*_check.py`
изменяют данные. Запускайте их только на одноразовой базе `iris_wazuh_test` с
`WAZUH_DISPOSABLE_TEST_DB=yes`; не запускайте на рабочей базе IRIS.
